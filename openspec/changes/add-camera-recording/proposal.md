# Proposal

## Why

지금 서버는 카메라 영상을 WebRTC로 실시간 전달만 하고 아무것도 남기지 않는다. 프로젝트 목표의 다음 단계는 카메라 영상을 저장해 나중에 파일 기반으로 다시 재생하는 것이다. 이 change는 그 앞부분인 저장을 맡는다. 등록한 카메라를 항상 녹화하고, 정해진 분량만 보관하며, 비정상 종료 뒤에도 남은 녹화를 믿을 수 있게 복구한다. 녹화본을 웹에서 재생하는 것(HLS, 타임라인)은 다음 change(`add-recording-playback`)에서 하며, 이 change의 파일 형식과 색인은 그 재생을 전제로 정한다.

## What Changes

- 등록한 카메라를 서버가 실행되는 동안 항상 녹화한다.
  - 저장 위치는 `<녹화 디렉터리>/<카메라 이름>/`이다. 녹화 디렉터리는 `--record-dir`(기본값 `recordings`)로 정한다.
  - 같은 이름의 폴더가 이미 있으면 그 폴더에 이어서 녹화한다.
  - 카메라가 없으면 녹화 디렉터리를 만들지 않는다.
- 녹화 파일은 fMP4(fragmented MP4)다.
  - GOP 하나(키프레임부터 다음 키프레임 전까지)가 조각(`moof`+`mdat`) 하나다.
  - 파일은 `--record-segment`(기본 60초) 단위로 나눈다. 단위 경계 뒤 첫 키프레임에서 새 파일을 연다.
  - 파일 이름은 그 파일의 시작 시각(초 단위)이다. 한 번 닫은 파일은 다시 열지 않는다.
  - 카메라가 끊기거나 다시 연결되면 쓰던 파일을 닫고, 다음 키프레임부터 새 파일을 연다.
- 프레임 시각은 파일 첫 키프레임을 받은 순간의 서버 시계에 카메라 RTP 타임스탬프의 차이를 더해 정한다.
  - 파일마다 기준을 새로 잡으므로, 카메라와 서버의 시계 차이가 파일 하나 이상 쌓이지 않는다.
- 카메라가 꺼졌거나 서버가 꺼져 있던 구간에는 아무것도 쓰지 않는다. 그 구간은 색인에 녹화가 없는 구간으로 남는다.
- 파일 쓰기, 동기화, 삭제는 이벤트 루프와 다른 녹화 스레드에서 한다.
  - 이벤트 루프는 GOP를 모아 파일 분할과 시각을 정하고, 완성된 GOP를 복사해 작업 큐로 넘긴다.
  - 키프레임이 왔을 때 큐에 쌓인 크기가 64MiB 이상이면 그 키프레임부터 시작하는 GOP를 버린다.
- 패킷 손실이나 큐 넘침으로 프레임을 버리면 파일을 닫지 않는다. 버리기 직전 프레임의 길이를 다음에 기록하는 키프레임까지 늘려, 그 구간은 마지막 화면이 멈춘 채로 재생된다. 녹화가 비는 구간은 카메라가 꺼졌을 때(끊김)뿐이다.
- 쓴 데이터는 `--record-sync`(기본 10초)마다, 그리고 파일을 닫을 때 디스크와 동기화한다.
- 녹화 파일마다 같은 이름의 색인 파일(`.idx`)을 둔다.
  - 조각마다 시각, 파일 안 위치와 길이, CRC32를 기록한다.
  - 색인 레코드에도 체크섬을 둔다.
- 보관 규칙
  - 평상시에는 카메라마다 녹화 분량이 `--record-retention`(기본 300초)을 넘지 않도록 가장 오래된 파일부터 지운다. 꺼져 있던 시간은 분량에 넣지 않는다.
  - 녹화 디렉터리가 있는 파일 시스템의 여유 공간이 `--record-min-free`(기본 1024MiB)보다 적으면, 모든 카메라 폴더에서 가장 오래된 단위 구간의 파일을 함께 지운다. 등록에서 빠진 카메라의 폴더도 여기에 포함한다.
  - 디스크가 꽉 차서 쓰기에 실패하면 같은 방식으로 지우고 다시 시도한다.
- 서버를 시작할 때 녹화 디렉터리가 있으면 카메라 유무와 관계없이 녹화를 복구한다.
  - 색인 레코드의 체크섬과 조각의 CRC32가 맞는 데까지만 믿는다.
  - 그 뒤의 영상 데이터와 색인 레코드는 잘라 낸다.
- `--camera`의 카메라 이름은 폴더 이름이 되므로 `/`가 들어간 이름, `.`, `..`, 255바이트를 넘는 이름을 거부한다. **BREAKING**: 이전에는 이런 이름도 받았다.
- README에 녹화 인자와 녹화 파일 확인 방법(`ffprobe`, `ffplay`)을 적는다.

범위 밖:

- 녹화본 재생: HLS 재생 목록, 녹화 구간 API, HTTP `Range`, 웹 타임라인과 검은 화면 표시. 다음 change에서 한다.
- 녹화 시작·중지 API와 카메라별 녹화 설정
- 색인에 없는 영상 데이터를 fMP4 구조 검사로 되살리는 복구
- 연결 중 해상도나 SPS·PPS가 바뀌는 경우의 파일 분할
- 카메라 SD 카드 녹화를 받아 빈 구간을 채우는 것
- 카메라별 큐, 과부하 때 키프레임만 남기기 같은 쓰기 지연 대책

## Capabilities

### New Capabilities

- `camera-recording`: 등록한 카메라의 영상을 fMP4 파일로 디스크에 저장하는 동작. 녹화 디렉터리와 파일 구성, 시각 기준, 색인, 디스크 동기화, 보관과 비상 삭제, 시작할 때의 복구, 녹화 인자를 다룬다.

### Modified Capabilities

- `rtsp-camera-source`: "카메라 등록 인자"의 카메라 이름 규칙에 폴더 이름으로 쓸 수 없는 이름의 거부를 더한다.

## Impact

- 새 코드
  - `src/recording/`: fMP4 조각·초기화 구간 작성, 색인 파일 읽기·쓰기, 카메라별 녹화 상태(GOP 모으기, 시각 계산, 파일 분할), 녹화 스레드와 작업 큐, 보관·비상 삭제, 시작할 때의 복구
  - 대응하는 `tests/recording/`
- 바뀌는 코드
  - `src/apps/web_server/main.cpp`: 녹화 인자, 카메라 이름 검사, 녹화기 생성과 종료
  - `README.md`, `CMakeLists.txt`, `.gitignore`(`recordings/`)
- 의존성: 새 라이브러리는 없다. 스레드는 C++ 표준 라이브러리로 만든다. `ffprobe`·`ffplay`는 수동 확인에만 쓰고 빌드와 자동 테스트에는 필요하지 않다.
- 호환성: 카메라를 등록하면 실행 위치에 `recordings/`가 생긴다. 카메라 이름 규칙이 좁아진다.
