# Spec Delta

## ADDED Requirements

### Requirement: 동영상 디렉터리 실행 설정
서버는 동영상 디렉터리(`--video-dir <경로>`)와 재생 속도(`--video-fps <1-120>`, 기본 30)를 명령행 인자로 받아야 한다(SHALL). `--video-dir`이 없으면 동영상 없이 실행하며, 이때 시그널링·ICE·DTLS 동작은 그대로이고 미디어는 보내지 않는다. `--video-fps`는 목록의 모든 동영상에 적용한다. `--video-fps`가 정수가 아니거나 범위를 벗어나면 원인과 사용법을 표준 오류에 출력하고 0이 아닌 종료 코드로 끝난다.

#### Scenario: 동영상 없이 실행
- **WHEN** `--video-dir` 없이 서버를 실행하고 연결 확인 페이지에서 연결한다
- **THEN** 연결 상태는 `connected`가 되고, 서버는 RTP 패킷을 보내지 않는다

#### Scenario: 잘못된 fps
- **WHEN** `--video-fps 0` 또는 `--video-fps abc`로 실행한다
- **THEN** 서버는 원인과 사용법을 표준 오류에 출력하고 0이 아닌 종료 코드로 끝난다

#### Scenario: 없어진 인자
- **WHEN** `--video-file a.h264`로 실행한다
- **THEN** 서버는 알 수 없는 인자라는 원인과 사용법을 출력하고 0이 아닌 종료 코드로 끝난다

### Requirement: 동영상 목록 구성
서버는 시작할 때 `--video-dir` 바로 아래 항목 중 디렉터리가 아니고(심볼릭 링크는 가리키는 대상으로 판단) 확장자가 대소문자 구분 없이 `.h264` 또는 `.264`인 것을 이름의 바이트 순서로 읽어 동영상 목록을 만들어야 한다(SHALL). 파일 이름이 동영상 ID다. 하위 디렉터리와 다른 확장자의 항목은 무시한다. 디렉터리를 열 수 없거나 디렉터리가 아니면 원인을 표준 오류에 출력하고 0이 아닌 종료 코드로 끝난다.

#### Scenario: 대상 파일 고르기
- **WHEN** 디렉터리에 `b.h264`, `A.264`, `c.mp4`, 하위 디렉터리 `sub/`가 있다
- **THEN** 목록은 `A.264`, `b.h264` 순서의 두 동영상이다

#### Scenario: 디렉터리가 아님
- **WHEN** 일반 파일 경로를 `--video-dir`로 지정한다
- **THEN** 서버는 원인을 표준 오류에 출력하고 0이 아닌 종료 코드로 끝난다

### Requirement: 잘못된 파일 건너뛰기
서버는 목록 대상 파일 중 쓸 수 없는 파일을 건너뛰고, 파일마다 경로와 원인을 경고로 표준 오류에 남겨야 한다(SHALL). 쓸 수 없는 파일은 읽기 실패, 64MiB 초과, 읽기 규칙이나 시작 조건 검증 실패, 이름이 UTF-8이 아님, 읽으면 목록 전체 파일 크기 합계가 256MiB를 넘는 경우다. 건너뛴 뒤 목록이 비면 원인을 출력하고 0이 아닌 종료 코드로 끝난다. 시작에 성공하면 동영상마다 ID와 프레임 수를, 마지막에 동영상 수와 fps를 로그에 남긴다.

#### Scenario: 일부 파일이 잘못됨
- **WHEN** 정상 파일 `ok.h264`와 시작 코드가 없는 `bad.h264`가 있는 디렉터리로 실행한다
- **THEN** 서버는 `bad.h264`를 건너뛴다는 경고를 남기고 시작하며, 목록에는 `ok.h264`만 있다

#### Scenario: 쓸 수 있는 파일이 없음
- **WHEN** 대상 파일이 없거나 모두 잘못된 디렉터리로 실행한다
- **THEN** 서버는 쓸 수 있는 동영상이 없다는 원인을 출력하고 0이 아닌 종료 코드로 끝난다

#### Scenario: 합계 상한
- **WHEN** 각각 64MiB 이하이지만 이름 순서로 합계가 256MiB를 넘는 파일들이 있다
- **THEN** 합계가 상한을 넘게 만드는 파일부터 건너뛴다는 경고를 남기고, 앞의 파일들로 시작한다

## MODIFIED Requirements

### Requirement: Annex-B 파일 읽기
서버는 목록 대상 파일마다 파일 전체를 읽어, 시작 코드(`00 00 01` 또는 `00 00 00 01`)로 구분된 H.264 NAL 단위로 나눠야 한다(SHALL). 파일을 열거나 읽을 수 없거나, 크기가 64MiB를 넘거나, NAL 단위가 하나도 없으면 그 파일은 쓸 수 없는 파일이며 "잘못된 파일 건너뛰기"를 따른다.

#### Scenario: 정상 파일
- **WHEN** README의 ffmpeg 명령으로 만든 10초 30fps 파일이 든 디렉터리로 서버를 실행한다
- **THEN** 서버는 시작하고, 그 파일의 프레임 수 300과 fps 30을 로그에 남긴다

#### Scenario: 없는 파일
- **WHEN** 디렉터리에 없는 파일을 가리키는 심볼릭 링크 `gone.h264`가 있다
- **THEN** 서버는 `gone.h264`를 열 수 없다는 경고를 남기고 그 파일을 목록에 넣지 않는다

#### Scenario: H.264가 아닌 파일
- **WHEN** 디렉터리에 시작 코드가 없는 텍스트 파일 `note.h264`가 있다
- **THEN** 서버는 `note.h264`에 NAL 단위가 없다는 경고를 남기고 그 파일을 목록에 넣지 않는다

### Requirement: 재생 시작 조건 검증
서버는 각 파일의 첫 프레임이 SPS, PPS, IDR 슬라이스를 모두 포함하는지 확인해야 한다(SHALL). 그렇지 않으면 브라우저가 처음부터 디코딩할 수 없으므로 그 파일은 쓸 수 없는 파일이며 "잘못된 파일 건너뛰기"를 따른다. 반복 재생은 첫 프레임으로 돌아가므로 이 조건이 반복 재생의 시작점도 보장한다.

#### Scenario: IDR로 시작하지 않는 파일
- **WHEN** 디렉터리에 첫 프레임에 IDR 슬라이스가 없는 파일이 있다
- **THEN** 서버는 그 파일이 첫 프레임 조건을 만족하지 않는다는 경고를 남기고 목록에 넣지 않는다

## REMOVED Requirements

### Requirement: 동영상 파일 실행 설정
**Reason**: 여러 동영상 중에서 고를 수 있도록 파일 하나 대신 디렉터리를 받는다.
**Migration**: `--video-file <파일>` 대신 그 파일이 든 디렉터리를 `--video-dir <디렉터리>`로 지정하고, 웹 페이지에서 그 파일을 선택한다. "동영상 디렉터리 실행 설정"을 따른다.
