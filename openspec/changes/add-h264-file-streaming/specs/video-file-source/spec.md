# Spec Delta

## Purpose

서버가 재생할 H.264 동영상 파일을 명령행 인자로 받아 시작할 때 읽고, 프레임 단위로 나누어 검증한다. 이후 MP4 같은 컨테이너나 카메라 녹화 파일도 같은 역할의 소스로 추가된다.

## ADDED Requirements

### Requirement: 동영상 파일 실행 설정
서버는 재생할 파일 경로(`--video-file <경로>`)와 재생 속도(`--video-fps <1-120>`, 기본 30)를 명령행 인자로 받아야 한다(SHALL). `--video-file`이 없으면 동영상 없이 실행하며, 이때 시그널링·ICE·DTLS 동작은 그대로이고 미디어는 보내지 않는다. `--video-fps`가 정수가 아니거나 범위를 벗어나면 원인과 사용법을 표준 오류에 출력하고 0이 아닌 종료 코드로 끝난다.

#### Scenario: 동영상 없이 실행
- **WHEN** `--video-file` 없이 서버를 실행하고 연결 확인 페이지에서 연결한다
- **THEN** 연결 상태는 `connected`가 되고, 서버는 RTP 패킷을 보내지 않는다

#### Scenario: 잘못된 fps
- **WHEN** `--video-fps 0` 또는 `--video-fps abc`로 실행한다
- **THEN** 서버는 원인과 사용법을 표준 오류에 출력하고 0이 아닌 종료 코드로 끝난다

### Requirement: Annex-B 파일 읽기
서버는 시작할 때 `--video-file`의 파일 전체를 읽어, 시작 코드(`00 00 01` 또는 `00 00 00 01`)로 구분된 H.264 NAL 단위로 나눠야 한다(SHALL). 파일을 열거나 읽을 수 없거나, 크기가 64MiB를 넘거나, NAL 단위가 하나도 없으면 원인을 표준 오류에 출력하고 0이 아닌 종료 코드로 끝난다. 시작에 성공하면 파일 경로, 프레임 수, fps를 로그에 남긴다.

#### Scenario: 정상 파일
- **WHEN** README의 ffmpeg 명령으로 만든 10초 30fps 파일로 서버를 실행한다
- **THEN** 서버는 시작하고, 프레임 수 300과 fps 30을 로그에 남긴다

#### Scenario: 없는 파일
- **WHEN** 존재하지 않는 경로를 `--video-file`로 지정한다
- **THEN** 서버는 원인을 표준 오류에 출력하고 0이 아닌 종료 코드로 끝난다

#### Scenario: H.264가 아닌 파일
- **WHEN** 시작 코드가 없는 텍스트 파일을 `--video-file`로 지정한다
- **THEN** 서버는 NAL 단위가 없다는 원인을 출력하고 0이 아닌 종료 코드로 끝난다

### Requirement: 프레임 분할
서버는 NAL 단위를 액세스 단위(프레임)로 묶어야 한다(SHALL). 새 프레임은 이전 프레임에 슬라이스(NAL 유형 1 또는 5)가 이미 있는 상태에서 AUD(9), SPS(7), PPS(8), SEI(6)가 오거나, `first_mb_in_slice`가 0인 슬라이스가 올 때 시작한다. 경계 판정에 쓰지 않는 NAL 유형(필러 데이터 등)은 현재 프레임에 포함한다. 슬라이스가 없는 프레임(파일 끝의 매개변수 집합만 남은 경우 등)은 버린다.

#### Scenario: 매개변수 집합과 IDR
- **WHEN** SPS, PPS, IDR 슬라이스, 일반 슬라이스, 일반 슬라이스 순서의 NAL로 이루어진 데이터를 나눈다
- **THEN** 프레임은 3개이고, 첫 프레임은 SPS·PPS·IDR 슬라이스를, 나머지는 각각 슬라이스 하나를 포함한다

#### Scenario: 한 프레임의 여러 슬라이스
- **WHEN** `first_mb_in_slice`가 0인 슬라이스 뒤에 0이 아닌 슬라이스가 이어진다
- **THEN** 두 슬라이스는 같은 프레임에 속한다

### Requirement: 재생 시작 조건 검증
서버는 첫 프레임이 SPS, PPS, IDR 슬라이스를 모두 포함하는지 확인해야 한다(SHALL). 그렇지 않으면 브라우저가 처음부터 디코딩할 수 없으므로 원인을 표준 오류에 출력하고 0이 아닌 종료 코드로 끝난다. 반복 재생은 첫 프레임으로 돌아가므로 이 조건이 반복 재생의 시작점도 보장한다.

#### Scenario: IDR로 시작하지 않는 파일
- **WHEN** 첫 프레임에 IDR 슬라이스가 없는 데이터를 읽는다
- **THEN** 서버는 첫 프레임 조건을 만족하지 않는다는 원인을 출력하고 0이 아닌 종료 코드로 끝난다
